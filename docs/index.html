How this stays current: a GitHub Actions workflow in this repo (.github/workflows/update-prices.yml) re-runs the Scrapling scrapers on a schedule and commits a fresh data/prices.json. This page fetches that file straight from GitHub every time it loads — reload it any time to see the latest committed data. It cannot scrape the retailer sites itself: browser security (CORS) blocks a static page like this from calling digicape.co.za or istore.co.za directly, which is exactly why the scraping has to happen in the scheduled workflow rather than in this page's JavaScript. If data/prices.json doesn't exist yet (workflow hasn't run for the first time), or the fetch fails for any reason, this page falls back to the snapshot baked in at the time this page was built. Coverage notes: iPhone/Watch model names vary enough between retailers that matching across sites is heuristic (see scripts/combine.py) — some genuinely-identical products may show up as separate unmatched cards rather than one merged row. Full Accessories and Apple TV catalogs are large and only partially represented here.
