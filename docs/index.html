How this works, and where it can be wrong

Every price is fetched directly from each retailer's own site by a scheduled GitHub Actions workflow in this repo (.github/workflows/update-prices.yml) — no manual price entry. Digicape's current hardware families and advertised starting prices come from its live category pages; competitor prices come from matched product pages. "Unavailable" means the fetch was blocked or no price could be confidently extracted — never a guess. A product only appears above once Digicape has returned a real price in the run that produced the data you're looking at; if Digicape's fetch fails, that product drops off the list entirely rather than showing a stale reference price.

Two retailers are worth extra scepticism: Takealot and Amazon SA both run bot-detection that can block plain server-side requests outright, redirect to a CAPTCHA, or serve a JS-only shell with no price in the initial HTML. If those columns show mostly "unavailable", that's very likely why — not that the products vanished. Digicape, Incredible Connection and iStore are more standard storefronts and tend to scrape more reliably, though Incredible Connection's Apple range is thinner since it isn't a dedicated Apple reseller.

Product matching across retailers is heuristic (see scripts/combine.py) — different retailers name the same model differently, and a row carrying a "different variant" flag means the cheaper price is for a different storage/chip/colour configuration, not a true like-for-like match.
